单个应用的同步与异步抽取使用同一请求结构；以下说明文件、兼容输入和按能力生效的参数。

## 身份与文件输入兼容

新集成推荐`app_id`加一个文件来源（`file_url`或`file_base64`）。历史调用也接受成对`app_key`/`app_secret`，仍必须发送`X-API-Key`请求头；`app_code`不是鉴权凭证。不要混用两套应用身份：同时给出完整key/secret和app_id时，完整key/secret优先。

旧单应用接口同时给出有效URL和Base64时优先Base64，未提供任何可用文件来源会报错。推荐始终只传一个；该兼容行为不适用于独立分类或自动路由，这两个新接口仍严格要求文件来源二选一。未知顶层字段可能被忽略，不代表会启用新功能。
```json
{
  "app_key": "YOUR_LEGACY_APP_KEY",
  "app_secret": "YOUR_LEGACY_APP_SECRET",
  "file_url": "https://files.example.com/materials.pdf"
}
```

## model_params 参数适用范围

| 参数 | 适用范围与规则 |
| --- | --- |
| `scale` | 页面图片转换比例，默认1；不保证影响原生XLSX/Markdown |
| `pages` | 原始页码；原生Markdown只有逻辑页1 |
| `disable_collaboration` | 同步默认1；1425同步/异步均强制1，不能开启人机协同 |
| `keep_content` | 经典抽取的大文档解析结果返回链接时，可同时保留内联内容；不使1425返回解析结果 |
| `page_task_timeout_seconds` | 大文档解析结果逐页整理/上传的等待时限，不是每页推理或整次抽取超时 |
| `card_type` | 仅支持卡证选择的应用；显式顶层card_type优先 |
| `enable_multi_ticket` | 仅具备多票能力的应用；显式顶层同名参数优先，均省略默认true |
| `temperature` / `top_p` / `max_tokens` | 扩展字典接受这些键不代表可调；当前1425/1423/1424不会用它们覆盖调用配置，不应依赖其效果 |

单应用的回标、翻译和置信度临时开关仍放在顶层；只有路由接口把三个开关放在model_params中。不能通过参数让不具备相应能力的应用获得该能力。

## 原生XLSX与Markdown

单应用抽取不应套用分类/路由仅PDF、PNG、JPEG的限制。经典自定义抽取、1425及1423/1424具有原生XLSX和Markdown处理入口，具体可用性仍以部署版本与能力授权为准。使用Base64时提供`file_name`及正确扩展名。

Markdown按完整源文档作为一个逻辑页处理，`pages`只应选择1，不因分隔线拆页，也不抓取链接图片另行识别。XLSX按可见Sheet和内嵌图片实例折算处理单元，具体数值以`spreadsheet_billing`为准；结果可提供原生预览清单URL。1425即使传with_rec_result=true也不返回解析结果。
```json
{
  "app_id": "8f4b2c506df811f1a3d90242ac120002",
  "file_url": "https://files.example.com/contracts.xlsx",
  "file_name": "contracts.xlsx",
  "enable_highlight": true
}
```
