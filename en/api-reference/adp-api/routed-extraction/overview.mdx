Classify by app name and description, extract each document instance with its matching app, and return grouped results.

## Prepare applications

Candidates are 1425 high-speed custom extraction, 1423 high-speed global invoices and 1424 Southeast Asia invoices. Set the app name and optional description through create, and retain app_id. Up to 10 distinct IDs and distinct trimmed case-insensitive names per request. A page may match multiple apps; separate instances matched to the same app are extracted separately.

## Synchronous call

    "a169e8d06df811f19b5e0242ac120002"

  "model_params": {
    "pages": [
      1,
      2,
      3,
      4,
      5
    ],
    "enable_highlight": true,
    "enable_field_value_translation": false,

}

Provide exactly one of file_url/file_base64. PDF/PNG/JPEG up to 100 MB and 260 original pages. pages uses distinct original 1-based pages. Put three optional switches inside model_params beside pages; they affect all children/instances in this request. Omitted/null inherits each selected config, and true/false temporarily overrides it without saving an app/version.

## Results and asynchronous calls

extraction_result groups by app; each object_values entry is one instance and pages always refers to the original file. Results are not duplicated as tickets or instance_id. Failed instances include error without discarding successes; unmatched pages appear in unclassified_pages. States: success, partial_success or failed. All-unmatched input succeeds with empty results. The example omits invoice results and some fields to focus on structure.

Async creation uses the same request, initially returning task_id/pending, followed by running/success/partial_success/failed on query. Accepted tasks keep their selected configuration and overrides. A sync task_id identifies the call and does not create a queryable async task.
