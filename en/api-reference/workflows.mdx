Workflow applications combine document processing, business decisions, human review, and result delivery into repeatable business processes. They are suitable for multi-document or multi-step scenarios, especially when a single extraction API is not sufficient or conditional decisions are required.

<Warning>
  OpenAPI does not currently support creating custom workflows. Go to the [official ADP platform](https://adp-global.laiye.com/?utm_source=apidoc) and use the AI conversational assistant to describe your business requirements and create a workflow. Test and publish it in the platform before using the OpenAPIs in this section to discover and run it.
</Warning>

## Create and call a workflow

1. **Choose how to create it**: Use an existing business workflow template, or use the AI conversational assistant in the official ADP platform to create a custom workflow.
2. **Create and publish the application**: For an official template, call [Create an application from a workflow template](/en/api-reference/adp-api/application-management/create-workflow-application-from-template) to obtain a runnable application. Test and publish custom workflows in the platform.
3. **Obtain the application ID**: For an application created from a template, use `data.application_id` from the creation response. For an application created and published on the website, use the `id` returned by List runnable workflow applications.
4. **Run the workflow**: Choose synchronous execution when you need to wait for the result, or create an asynchronous task and then query, rerun, or cancel the run as needed.

<Info>
  For templates, we recommend querying templates, creating and publishing an application, then uploading files and running it. Alternatively, pass a fixed template ID as `application_id` directly to a run endpoint: the service creates and publishes an account application if no corresponding runnable application exists, or reuses an existing one. See [Integrate business workflow templates](/en/api-reference/adp-api/application-management/business-workflow-templates) for examples. Workflow changes are currently available only through the ADP website interface; test and publish the modified application before running it through OpenAPI.
</Info>

Applications created from the accounts payable, expense reimbursement, and financial reporting templates share the run APIs in this section. See [Integrate business workflow templates](/en/api-reference/adp-api/application-management/business-workflow-templates) under Application Management for the templates and integration example.

## OpenAPI capabilities

| Goal | Endpoint |
| --- | --- |
| List business workflow templates | `GET /open/agentic_engine/laiye/v1/app/templates` |
| Create and publish an application from a workflow template | `POST /open/agentic_engine/laiye/v1/app/applications/create-from-template` |
| List workflow applications that the current account can run | `GET /open/agentic_engine/laiye/v1/app/applications` |
| Get workflow application details (limited preview) | `GET /open/agentic_engine/laiye/v1/app/applications/{application_id}` |
| Run a workflow synchronously | `POST /open/agentic_engine/laiye/v1/app/run` |
| Create an asynchronous run task | `POST /open/agentic_engine/laiye/v1/app/run/create/task` |
| Query an asynchronous run result | `GET /open/agentic_engine/laiye/v1/app/run/query/task/{run_id}` |
| Rerun or cancel a run | `POST /open/agentic_engine/laiye/v1/app/run/{run_id}/rerun`, `POST /open/agentic_engine/laiye/v1/app/run/{run_id}/cancel` |

OpenAPI supports business workflow template discovery, explicit application creation and publication, and direct execution with a fixed template ID that creates or reuses an account application. Published applications also support application queries and run management. Create, refine, and publish custom workflows in the official ADP platform.
